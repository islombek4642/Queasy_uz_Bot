# **5. Biznes logikasi – eng muhim qism**

Men tizimni quyidagi holatlar asosida qurishni tavsiya qilaman.

```

CREATED
   |
   v
WAITING
   |
   v
STARTING
   |
   v
IN_PROGRESS
   |
   v
QUESTION_RESULT
   |
   v
IN_PROGRESS
   |
   v
FINISHED

```

Qo‘shimcha holatlar:

- CANCELLED – host o‘yinni bekor qildi.
- EXPIRED – xona belgilangan muddatda boshlanmadi.
- DISCONNECTED – foydalanuvchi aloqadan uzildi.

**Har bir holatning vazifasi:**

| Holat           | Vazifasi                       |
| --------------- | ------------------------------ |
| WAITING         | O‘yinchilar yig‘iladi          |
| STARTING        | Countdown boshlanadi           |
| IN_PROGRESS     | Savolga javob beriladi         |
| QUESTION_RESULT | Javoblar va ballar hisoblanadi |
| FINISHED        | Yakuniy natijalar              |

### **Ball hisoblash**

Masalan, 100 ballik tizim:

- To‘g‘ri javob: 100 ball.
- Noto‘g‘ri javob: 0 ball.
- Javob bermaslik: 0 ball.
- Tez javob uchun qo‘shimcha bonus: 0–50 ball.

Shunda tez va to‘g‘ri javob bergan foydalanuvchi ko‘proq ball oladi.

### **Juda muhim texnik qoidalar**

1. Savol vaqti server tomonidan boshqarilishi kerak, foydalanuvchining telefonidagi timer emas.
2. Har bir savolga foydalanuvchi faqat bir marta javob bera olishi kerak.
3. Javob vaqti tugagach, yangi javoblar qabul qilinmasligi kerak.
4. Internet uzilib qayta ulansa, foydalanuvchi o‘yin holatiga qayta qo‘shilishi kerak.
5. To‘g‘ri javoblar frontendga o‘yin tugamaguncha yuborilmasligi kerak.
6. Barcha ballar serverda hisoblanishi kerak.

Telegram WebApp uchun bu juda muhim: frontendga ishonib qolmang, server yagona ishonchli manba bo‘lsin.

# **6. Backend arxitekturasi**

Agar Node.js ishlatayotgan bo‘lsangiz, quyidagi texnologiyalar yaxshi ishlaydi:

| Texnologiya      | Vazifasi                       |
| ---------------- | ------------------------------ |
| Node.js          | Backend                        |
| Socket.IO        | Real-time aloqa                |
| PostgreSQL       | Xonalar va natijalar           |
| Redis            | Jonli o‘yin holati va timerlar |
| Telegram Bot API | Taklif va bildirishnomalar     |

Oddiy ishlash mexanizmi:

```

Telegram WebApp
      |
      | WebSocket
      v
Node.js Backend
      |
      +------ Redis
      |       |
      |       +-- Room State
      |       +-- Active Timer
      |       +-- Player Status
      |
      +------ PostgreSQL
              |
              +-- Users
              +-- Quiz Results
              +-- Game History

```

Room uchun taxminiy ma'lumotlar:

```
{
  id: "room_8421",
  hostId: "user_1",
  status: "WAITING",
  mode: "REALTIME",
  maxPlayers: 10,
  currentQuestion: 0,
  players: [],
  settings: {
    questionCount: 15,
    questionTime: 20
  }
}
```

Har bir player uchun:

```
{
  userId: "user_1",
  score: 0,
  status: "READY",
  connected: true,
  answered: false
}
```

Bular konseptual strukturalar. Real loyihada javoblar, vaqt tamg‘alari, savollar va boshqa ma'lumotlar ham alohida boshqariladi.
